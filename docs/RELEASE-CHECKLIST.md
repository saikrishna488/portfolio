# Portfolio release procedure

1. Edit portfolio content in `dist/index.html`; run `python scripts/build-content.py` to refresh the recruiter view and project landing pages.
2. Run `node --test tests/*.cjs`, `python scripts/check-assets.py`, syntax-check each JS file, and `git diff --check`.
3. Browser-test open/close/minimize/maximize/snap/recover, move between spaces, session restoration, Back/Forward, direct links, search, project filtering, and keyboard focus return.
4. Check widths 320, 390, 768, 1024 and landscape 844×390. Include a real iOS/Android keyboard test before claiming physical-device compatibility.
5. Inspect console errors and missing requests. Verify external project links separately.
6. Keep `media/resume.pdf` and `media/resume-page-1.webp` paired. Updating the PDF requires regenerating its preview and checking HTML content against it; current PDF is preserved, not regenerated by the content builder.
7. Preserve the Sites project ID, audience, custom domain, and GitHub host configuration.
8. Save and deploy a new Sites version, verify the returned successful deployment and public page, then sync identical source/assets to GitHub.
9. Roll back by deploying the prior saved Sites version. Restore matching GitHub files with a revert commit, never a forced history rewrite.

## Verification limits
The browser fixture validates responsive CSS, not physical touch hardware, Safari, VoiceOver/TalkBack, or a real mobile keyboard. Node geometry tests exercise the window controller with DOM stubs, not browser pointer routing. These checks do not replace either browser interaction or real-device testing.
